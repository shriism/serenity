## Design Context

### Users
Personal power users managing their own knowledge, files, people, plans, and AI conversations during sustained desktop sessions. They need to move between connected records without losing their place, and to understand what the assistant can read and change.

### Brand Personality
Calm, modern, native, minimal, focused, and intelligent. Conversational but precise language; confidence should come from clear structure and provenance rather than decoration. The creator prefers the restraint of ChatGPT desktop and OpenCode over an enterprise dashboard.

### Aesthetic Direction
Quiet native document workspace rather than a dashboard. Retain soft near-black charcoal and a sparing muted periwinkle/indigo accent; default to dark while offering a coordinated light mode and OS-following appearance. Keep an Obsidian-like compact rail for reopenable sidebars, a dominant central document canvas, and an integrated right-hand AI companion that can expand across the center. Favor generous space, subdued panel surfaces, soft necessary boundaries, and progressive disclosure over repeated cards, loud labels, dividers, and prominent controls.

### Implementation Defaults
Existing Electron + React 19 + TypeScript + vanilla CSS app. Keep its bundled local font and lucide-react icons unless a measured change improves the whole system. Native HTML controls and project-specific components are the current component/form architecture; no shadcn, Radix, Base UI, table system, or virtualization layer is installed. On-device files and provider-backed Copilot/Codex requests remain the functional baseline. These are detected project defaults, not framework fallbacks.

### Design Principles
1. Give the active knowledge or planning task the center; put conversations, AI scope, and provider workflow in the right pane.
2. Make both sidebars independently reversible with persistent, labeled icon controls and keyboard-accessible toggles.
3. Keep navigation and context compact; use space and type to establish hierarchy before color or surfaces.
4. Make open-file context visible and truthful. The AI may read permitted active or open files; disclose what was actually sent with each reply.
5. Allow a chat focus mode without stranding the user's navigation or sacrificing an unsent message.
6. Make the active object visually dominant: quiet the navigation, place claims and advanced actions after the document, and put the assistant composer ahead of configuration.
