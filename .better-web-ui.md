# Serenity interface context

## Audience and character

Serenity serves people who manage connected notes, documents, relationships, plans, and AI conversations through long desktop sessions. They need to move between records without losing context and to understand what the assistant may read or change. The interface should feel calm, focused, native, and precise. Provenance and clear structure carry its sense of intelligence.

## Visual direction

Use soft charcoal by default, coordinated light and system appearances, and a restrained periwinkle accent. Keep the active page or record dominant, with readable line lengths, generous space, and subdued chrome. The left ribbon and explorer provide compact navigation; the assistant is a contextual partner on the right or a full-window chat. Home should show real knowledge, plans, recent activity, and review items without fabricated observations or dashboard metrics. Prefer typography and spacing to extra cards or dividers. Motion should explain changes and respect reduced-motion preferences.

## Implementation

The app uses Electron, React 19, TypeScript, vanilla CSS, bundled fonts, and lucide-react icons. Native HTML controls and project-specific components are the current UI system. The renderer is sandboxed; workspace files and provider requests run through the typed preload and main-process API. Keep provider-specific behavior behind that boundary.

## Interaction principles

1. Keep sidebar controls discoverable, independently reversible, and keyboard accessible.
2. Preserve the user's pane layout and unsent message when moving between workspace and full-window chat.
3. Make the focused resource and permitted context clear; disclose records actually sent to an AI provider.
4. Keep editing immediate, with visible save and conflict states.
5. Keep advanced controls available without competing with the content or composer.
